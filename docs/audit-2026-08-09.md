## Overall: **4 / 10 — NOT launch-ready.**

Weighted for what this product IS (an adult-in-front-of-children marketplace about to
take money), the safety/legal and money blockers dominate the strong architecture.
The foundation is genuinely good (AI 8, schema 7); the launch surface is not close.

## Launch-BLOCKERS, ranked by blast radius

### RED — legal / child-safety (do not launch until true)
1. **"Background-checked" is a false claim.** No Checkr/Sterling/Onfido/Persona/any
   vendor in either repo (0 matches / 576 files); `background_check_status='verified'`
   is written *only* by demo seed SQL; the public UI says "identity and criminal-record
   check before any booking" (`mod-safety.js:328`). The gate is built and ready to
   receive a vendor webhook — but until a vendor exists, either integrate one or remove/
   soften every "background-checked / criminal-record check" claim.
2. **Per-child media consent exists only in the sim.** `mod-media.js` shows a 3-tier
   parent-controlled photo gate; the backend has **no** athlete-media table, **no**
   consent-tier column, and its one media bucket is **public-read**
   (`20260801_000200`). Do not ship child-media features on the shown design.
3. **COPPA consent is a checkbox, not verifiable; no age gate.** DB enforces consent
   *presence* (`20260728_000203`), but the age gate + verifiable-parental-consent flow
   are `Status: staged` (`docs/COPPA-AGE-GATE-DESIGN.md:72`). §312.5 wants *verifiable*.

### RED — money / supply (do not take real money until fixed)
4. **29 migrations authored-but-NOT-applied.** Prod stops at `20260725033343`; every
   payments/capacity fix (`platform_fees`, `group_seats`, capacity trigger, camps,
   commission) sits unapplied. A policy that never ran protects nobody.
5. **Fee is three different numbers.** Charge default 10% (env, `stripe-create-checkout:49`),
   Dart preview 18/4 (`platform_fee.dart:31,34`), intended 12% appears **nowhere** in
   the backend. Pin one server-authoritative value; mirror the Dart preview to it.
6. **Collaborators cannot be paid through Stripe.** Membership model is authored
   (`organization_members`, `commission_rates`, `team_split.dart`) but every split is
   "DESIGN-ONLY, never wired live"; the charge is a single-destination transfer. Decide:
   build the transfer-split, or state orgs settle trainers off-platform (and stop the
   sim implying otherwise).
7. **Capacity not enforced at the DB in prod.** Correct trigger + `claim_group_seat`
   exist only as unapplied migrations → oversell reachable via direct insert for
   1:1/group/camp.
8. **Google coach signup drops the role to `searcher`.** OAuth query-param role is not
   copied into `raw_user_meta_data`; `handle_new_user` defaults `searcher`
   (`supabase_auth_service.dart:145`, `20260630_000001:23`). The coach wedge fails on
   the most-used button. No live self-service `claim_provider_role`.
9. **No org/facility self-serve signup.** The roster model is complete but has no front
   door — a facility must be hand-promoted to `provider_type='organization'`.
10. **Refunds not computed from a snapshotted policy** (`stripe-webhook:162` records the
    Stripe number as-is; no policy snapshot at purchase).

### RED — safety divergence (reconcile before launch)
11. **Two retrieval paths disagree on the child-safety intensity ceiling.** Free-text
    `searchProviders()` runs the client `_ceilingForAge` (1–3 scale, looser at ages
    6/8–11/13, ignores maturation); `aiMatch()` runs the server `ltad_max_tier` (0–4).
    Same child, two verdicts — the text path can show an over-intense program the AI
    path blocks. Route text search through `match_eligible`. (Not a vetting leak — the
    verified gate holds on both paths.)

### YELLOW — pre-launch trust
12. **Waitlist delivers nothing.** No write path in the web sim; prod `waitlist` is
    RLS-on / 0-policies → silent drop. A pre-launch site that drops signups is worse
    than no form.

### GREEN — sim-fixable now (this repo, no backend)
13. **Search origin is Miami coords labeled "Chicago."** `mod-search.js:28`
    `ORIGIN={lat:25.7617,lng:-80.1918,label:"Chicago, IL"}` — Miami's coordinates,
    shown to the user (`:354`), poisoning every distance sort. At least one seed still
    carries Miami coords (`host:8193`). **The one real live bug from the geo sweep.**
14. **Dead fabricated-model code.** `AI_MODELS` (Opus 5 / GPT-5.6 / Gemini…) array +
    "live routing server-side" comment + dead `cmdmodelpick` handler remain in source
    though the picker was collapsed — the exact fabricated-capability pattern removed.
15. **Type system drifted to 7 families** (Instrument Serif + Inter + Archivo + Syne +
    Hanken + Jakarta + JetBrains) vs CLAUDE.md rule 4's 2-register law. This is a
    **design decision to ratify**, not a silent slide — the per-page Archivo/Syne fonts
    were added this session; directive 6 of the migration brief says collapse to two.
16. Stale contract comments (Syne uppercase rationale), dataset count (6 vs 30),
    no CSP actually served (the whole inline-everything design is unforced).

## What is genuinely STRONG (say it plainly)

- **AI (8/10):** one `ai-gateway` chokepoint → real Anthropic; server-side model
  routing; Opus service-role-gated; grounding is a **structural SQL filter before the
  model** (`match_eligible`), then `matchguard` overwrites every fact and strips
  credential claims — a hallucinated coach/price cannot reach the UI. At-risk detection
  is deterministic SQL; AI writes are human-confirmed. Ship it (post gap-#6 fix).
- **Backend schema (7/10):** consent as a DB CHECK (no athlete row without verifiable-
  consent columns), per-human background gate wired into all four discovery/booking
  paths fail-closed, coaches cannot self-verify (trust columns server-controlled),
  reviews double-blind + completed-session-gated, org RLS with recursion-safe SECURITY
  DEFINER.
- **Deploy pipeline:** real and green — branch → PR → CodeRabbit → Vercel → live
  byte-verified.
